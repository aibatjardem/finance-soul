# Настройка Finance Soul в проекте

Цель: после этого опроса в папке проекта есть `.finsoul/` без `TBD`, первая модель `.finsoul/models/main/inputs.json` и её расчёт.

## Правила

- **Ничего не перезаписывай.** Файл уже есть — покажи, что в нём, и спроси, обновлять ли. Новые версии шаблонов клади рядом как `*.finsoul-new`, если пользователь не согласился заменить.
- Вопросы — через `AskUserQuestion`, по одному-два за раз, 2–4 варианта, рекомендуемый первым с пометкой «(Рекомендуется)». Всё на русском.
- Не выдумывай цифры за пользователя. Не знает — ставь оценку с пометкой «оценка» и рассуждением в `assumptions.md`.

## Шаги

1. **Проверь, что есть.** Прочитай `.finsoul/` целиком, если он существует. Найди `TBD`.
2. **Ядро работает?** Выполни `python3 "<путь к ядру>" check-env` (путь сообщает хук при старте сессии: строка «Ядро на этой машине»). Нет Python 3.9+ или openpyxl — скажи, что поставить, и продолжай без Excel (`--no-xlsx`).
3. **О бизнесе** (заполняет `company.md`):
   - новый бизнес или работающий;
   - что продаём и за что платят (единица продажи: подписка-месяц, заказ, час, штука);
   - для кого модель: инвестор / банк / госпрограмма / для себя — от этого зависит структура бизнес-плана;
   - горизонт (по умолчанию 36 мес.) и месяц старта;
   - юрлицо, налоговый режим, ставка КПН с источником (статья кодекса и дата, когда проверили).
4. **Профиль.** Предложи профиль по ответам (`blank` или `edtech`; список — папки `profiles/` плагина, рядом с ядром: `<плагин>/profiles/<имя>/`). Скопируй `company.md`, `metrics.md` профиля и шаблоны `assumptions.md`, `local/rules.md` из `<плагин>/templates/`.
5. **Показатели** (`metrics.md`): покажи список профиля, спроси, что убрать и что добавить; формулу каждого показателя запиши так, как её понимает пользователь.
6. **Первая модель.** Скопируй `inputs.json` профиля в `.finsoul/models/main/inputs.json` и пройди по нему вместе с пользователем: цена, переменные затраты на единицу, ramp по месяцам, постоянные затраты, капвложения, финансирование. Каждое число → строка в `assumptions.md` с источником и уверенностью (см. `finance-soul:assumptions`).
7. **Расчёт.** `python3 "<путь к ядру>" build .finsoul/models/main/inputs.json --out .finsoul/models/main/out`. Код 2 — покажи ошибки входов по одной и исправь вместе с пользователем. Код 1 — модель не сходится: не показывай выводы, разберись (см. `finance-soul:three-statement-guide`).
8. **Итог пользователю:** 3–5 строк из раздела «Итог» отчёта, главное предупреждение из `checks.json`, и что дальше: `finance-soul:model-auditor` для проверки, `finance-soul:cfo-reviewer` для разбора, `finance-soul:business-plan-guide` для бизнес-плана.
9. Предложи закоммитить `.finsoul/` в git (не в `.gitignore`): допущения — часть проекта.
