# Finance Soul — дизайн

Дата: 2026-11-21. Статус: v0.1 одобрена владельцем 2026-11-21 («да, делай v0.1»).

## Зачем

Владелец хочет один инструмент для Claude Code: «душу финансиста», устроенную как его `aibatjardem/agentsoul`. Её ставят в любую папку (проект, компания, идея), и дальше Claude работает с разными финансовыми показателями по одной дисциплине: финмодель, бизнес-план, юнит-экономика, cash/runway, оценка, план-факт. Набор показателей меняется от проекта к проекту, дисциплина — нет.

Логика взята из открытых проектов (клоны лежат в `/Volumes/TRANSCEND/claude/finance-soul-sources/`): `anthropics/financial-services` (3-statement, DCF, audit-xls, variance-commentary), `JeffBrines/openfpa` (cfo-judgment, cash-runway, monthly-close, ядро `pyfpa`), `Jakeschincariol/founder-skill` (founder-cfo: JSON → Python-скрипт → отчёт, каждое число прослеживается до входа), `lianghsun/open-sheet`, `modeleonai/modeleon` (модель кодом → живой Excel).

Успех: владелец ставит плагин, запускает `/finance-soul:setup` в папке проекта, отвечает на вопросы, просит «построй финмодель / бизнес-план / посчитай юнит-экономику», и получает отчёт и Excel с живыми формулами, где каждая цифра считается проверенным кодом и прослеживается до допущения с источником.

## Цели

- Плагин Claude Code с теми же тремя слоями, что в agentsoul: душа (хук при старте) → skills (по требованию) → субагенты (изолированные исполнители).
- **Расчётное ядро** на Python внутри плагина: все числа считает протестированный код, не LLM.
- Данные проекта — в самом проекте, в `.finsoul/`; плагин их не перезаписывает.
- Профили бизнеса с готовым набором показателей.
- Казахстанская специфика: KZT, налоги РК — ставки в отдельном файле данных с датой и источником.
- Русский язык текстов; поле `description` у skills и агентов — на английском (как в agentsoul: по нему Claude выбирает).

## Не-цели

- Не бухгалтерская система: нет журнала проводок, нет интеграции с 1С, банками, налоговой.
- Не инвестиционный советник: не даёт рекомендаций купить/продать, не торгует.
- Не GUI и не веб-приложение.
- Английская версия — не сейчас (структура не должна мешать добавить её позже).
- Не анализ публичных компаний по биржевым данным (LSEG, S&P, SEC filings) — это есть у `financial-services`.

## Анти-цели (провал, даже если «работает»)

- В отчёте есть число, которое нельзя проследить до входа или функции ядра.
- Баланс не сходится, а инструмент молчит.
- Оценка подана как факт; допущение без источника.
- Налоговая ставка устарела и не помечена датой проверки.
- Excel-файл с захардкоженными числами вместо формул там, где должна быть формула.
- Хук при старте ломает или заметно замедляет сессию.

## Ограничения

- На машине владельца **Python 3.9.7**, `openpyxl 3.1.5`, нет `uv`, нет LibreOffice. Ядро — Python ≥ 3.9 (без `match`, без `tomllib`), расчёты только на стандартной библиотеке; `openpyxl` — единственная внешняя зависимость и нужна только для Excel.
- Лимит `additionalContext` хука SessionStart — 10 000 символов (проверено при дизайне agentsoul 0.3).
- Лицензии источников: `financial-services` и `modeleon` — Apache-2.0, `openfpa`, `founder-skill`, `open-sheet`, `FinanceToolkit` — MIT: можно переиспользовать с указанием авторства (файл `NOTICE`). `ai-startup-skills`, `business-plan-skill` — некоммерческая лицензия; `burnless`, `CanvasDesk` — AGPL-3.0: **из них не копируется ни текст, ни код**, только идеи. Сам плагин — MIT.
- Субагентов вызывать по одному (предпочтение владельца).

## Подходы

| | Суть | За | Против |
|---|---|---|---|
| A. Только знания | Душа, методички, агенты; Excel собирается каждый раз заново | Легко, как agentsoul | Формулы и проверки пишутся с нуля, цифры плывут |
| **B. Знания + расчётное ядро** (выбран) | Плюс Python-ядро с тестами в плагине: расчёты, сведение трёх форм, проверки, выгрузка в Excel | Цифрам можно доверять; модель можно нести в банк/инвестору | Нужен Python 3 |
| C. Форк openfpa | Взять готовое ядро и память | Много готового | Заточен под план-факт действующей компании, английский, далеко от логики agentsoul |

Выбран **B** владельцем 2026-11-21. Причина: в финансах главная ценность — правильные цифры.

## Устройство

### Репозиторий `aibatjardem/finance-soul`

```
.claude-plugin/marketplace.json        маркетплейс: один плагин finance-soul
plugins/finance-soul/                  сам плагин (он же исходник — сборки нет)
├── .claude-plugin/plugin.json
├── hooks/                             SessionStart: сжатая душа + сводка .finsoul/
├── soul/                              core.md (сжатая душа для хука), full.md
├── skills/<name>/SKILL.md             методички, опросники, setup, справка по ядру
├── agents/<name>.md                   субагенты
├── templates/                         шаблоны файлов .finsoul/
├── profiles/<name>/                   профили бизнеса
└── kernel/finsoul/                    Python-пакет ядра + data/tax_kz.json
tests/                                 pytest: ядро + валидатор плагина
examples/                              сквозной пример (EdTech)
NOTICE, LICENSE (MIT), README.md, CLAUDE.md
```

Решение исполнителя: **без шага сборки**. В agentsoul сборка нужна из-за двух локалей; здесь одна, поэтому каталог плагина и есть исходник. Валидатор — тест на pytest (одна среда, Python).

### Данные проекта — `.finsoul/`

Отдельный каталог, не `.soul/`, чтобы finance-soul и agentsoul жили в одном проекте без конфликтов.

| Файл | Что внутри | Аналог в agentsoul |
|---|---|---|
| `company.md` | отрасль, стадия, модель выручки, валюта, налоговый режим РК, горизонт, для кого модель (инвестор / банк / госпрограмма / себе) | `stack.md` |
| `metrics.md` | какие показатели отслеживаем и **точная формула каждого** в этом проекте | `glossary.md` |
| `assumptions.md` | реестр допущений: значение, единица, источник, уверенность (факт / публичная цена / оценка), дата | — |
| `local/*.md` | правила проекта, сильнее всего остального | `local/*.md` |
| `models/<имя>/inputs.json` | входы конкретной модели | — |
| `models/<имя>/out/` | `report.md`, `model.xlsx`, `checks.json` — генерируются | — |

### Душа — красные линии

- Числа считает ядро, не «в уме». Нет функции в ядре — сначала функция с тестом, потом число.
- Каждое число в отчёте прослеживается до входа в `inputs.json` и допущения в `assumptions.md`.
- Оценка всегда помечена как оценка, с рассуждением; не выдаётся за факт.
- Прибыль ≠ деньги: cash flow считается всегда, даже если просили только P&L.
- Баланс сходится, кэш сходится с CF, нераспределённая прибыль сворачивается — иначе модель не выдаётся.
- Минимум три сценария (базовый / оптимистичный / пессимистичный) и чувствительность к ключевым драйверам.
- Ramp (выход на план) — главное место, где врут планы: первый месяц почти никогда не равен плановому объёму.
- Налоги — по `tax_kz.json` с датой проверки; если дате больше 6 месяцев — предупредить.
- Не даёт инвестиционных советов; результат — черновик для проверки человеком.

Иерархия правил: `.finsoul/local/*.md` > душа и skills finance-soul > стандартные настройки Claude Code.

### Ядро `finsoul`

Python ≥ 3.9, расчёты на `decimal`/`float` стандартной библиотеки. CLI: `python3 "${CLAUDE_PLUGIN_ROOT}/kernel/run.py" <команда> <inputs.json> --out <папка>`. Входы — JSON (stdlib; схема на каждую команду), выходы — `report.md` + `checks.json` (+ `model.xlsx` по флагу).

| Модуль | Что считает |
|---|---|
| `tvm` | NPV, IRR, XNPV/XIRR, простая и дисконтированная окупаемость, аннуитет и график кредита |
| `unit_economics` | маржинальный доход на единицу, точка безубыточности, CAC, LTV, LTV/CAC, окупаемость CAC, когорты с оттоком |
| `cash` | помесячный денежный поток, runway, пиковая потребность в финансировании, 13-недельный прогноз |
| `three_statement` | связанные P&L, баланс, ДДС (помесячно и по годам): амортизация, оборотный капитал (DSO/DIO/DPO), кредиты, налоги; проверки целостности |
| `scenarios` | базовый/оптимистичный/пессимистичный, чувствительность (торнадо), точки слома |
| `valuation` | DCF: WACC, терминальная стоимость (Гордон и мультипликатор), проверка доли TV |
| `variance` | план-факт, разложение на цену / объём / структуру |
| `tax_kz` | налоги РК по `data/tax_kz.json` (КПН, НДС, ИПН, социальные платежи, спецрежимы): ставка, порог, источник, дата проверки |
| `excel` | выгрузка в xlsx **с живыми формулами**, генерируется из того же описания модели, что и расчёт |
| `audit` | проверка xlsx: хардкод в зонах формул, битые ссылки, сходимость баланса |

Ставки `tax_kz.json` исполнитель **проверяет по первоисточникам на дату реализации** (с 2026 года в РК действует новый Налоговый кодекс) и записывает источник и дату у каждой ставки.

### Skills (разговор и знание)

- `setup` — создаёт `.finsoul/`: спрашивает о бизнесе, предлагает профиль, ставит шаблоны.
- `company-initializer`, `metrics-initializer` — опросники, заполняют `company.md` и `metrics.md`.
- `assumptions` — как вести реестр допущений, иерархия источников (документы владельца → публичные цены → оценка).
- Методички: `three-statement-guide`, `unit-economics-guide`, `cash-runway-guide`, `valuation-guide`, `plan-fact-guide`, `business-plan-guide` (структура под инвестора, банк, госпрограмму РК), `kz-tax-guide`, `metrics-library` (определения показателей по профилям).
- `kernel-reference` — команды ядра, схемы входов, как читать `checks.json`.
- `soul` — полный текст души и карта команды.

### Субагенты

Только читают и советуют: `model-auditor` (по мотивам `audit-xls`), `cfo-reviewer` (по мотивам `fpa-cfo-judgment`: интерпретация цифр, красные флаги), `market-researcher` (TAM/SAM/SOM, конкуренты, цены — с источниками).
Могут писать файлы: `model-builder` (входы → ядро → отчёт и xlsx), `unit-economics-analyst`, `cash-analyst`, `valuation-analyst`, `variance-analyst`, `business-plan-writer`.

Как в agentsoul: агент сначала читает `.finsoul/`; если там `TBD` или файлов нет — stop-режим и подсказка запустить нужный опросник. В агентах — только поля `name`, `description`, `tools`, `model`, `skills`.

### Профили бизнеса

`blank`, `saas`, `edtech`, `ecommerce`, `services`, `production`. Профиль = заполненные заготовки `company.md`, `metrics.md` и шаблон `inputs.json`.

### Хук при старте

Отдаёт сжатую душу (`soul/core.md`) и сводку `.finsoul/` (что заполнено, какие модели есть, дата проверки налогов); нет `.finsoul/` — подсказывает `/finance-soul:setup`. Бюджет — меньше 10 000 символов, проверяется тестом. Ошибка в хуке не ломает сессию.

### Установка для пользователя

1. `/plugin marketplace add aibatjardem/finance-soul`
2. `/plugin install finance-soul@finance-soul`
3. В папке проекта: `/finance-soul:setup`.

## Этапы (решение владельца 2026-11-21: «быстро», сначала v0.1)

**v0.1** — строится сейчас:

- ядро: `tvm`, `unit_economics`, `cash`, `three_statement` + проверки целостности, `scenarios` (три сценария как прогон с множителями), `excel` с живыми формулами;
- методички: `three-statement-guide`, `unit-economics-guide`, `cash-runway-guide`, `business-plan-guide`;
- агенты: `model-builder`, `model-auditor`, `cfo-reviewer`;
- профили: `blank`, `edtech`; пример `examples/edtech/`;
- публичный репозиторий `aibatjardem/finance-soul`.

**v0.2** — следующий заход: `valuation` (DCF), `variance` (план-факт), `tax_kz` со сверкой по Налоговому кодексу РК 2026, `audit` чужих xlsx, остальные агенты и профили, отдельные опросники `company-initializer`/`metrics-initializer`. В v0.1 налоги — параметры во входах модели (ставка КПН/НДС задаётся пользователем с источником), без справочника.

### Решения исполнителя для v0.1 (после проверки дизайна)

- **Формулы в Excel.** Небольшой слой «описание модели»: каждая строка — имя, формула над другими строками и входами. Из одного описания ядро и считает значения в Python, и пишет формулы в xlsx. Живые формулы — у трёх форм, cash/runway и юнит-экономики; NPV/IRR — встроенными функциями Excel. modeleon не используем: ему нужен Python 3.12+ и numpy.
- **Сценарии.** Один лист «Входы» с ячейкой-переключателем сценария (базовый/оптим./пессим.) и множителями драйверов; формулы читают активный сценарий. `report.md` показывает все три, их считает ядро.
- **Налоги в v0.1.** НДС сквозной: выручка и затраты во входах — без НДС, НДС через баланс не проводится. КПН — ставка из входов (с источником), убыток прошлых лет переносится. Правовые формы и спецрежимы — в v0.2.
- **Валюта.** Одна валюта модели (по умолчанию KZT), поле `currency` во входах. Курсы и валютные кредиты — в v0.2; схема входов оставляет под них место (`fx` — необязательный блок).
- **`model-auditor` в v0.1** проверяет только модели самого плагина (`checks.json` + формулы в xlsx). Аудит чужих xlsx — v0.2.
- **Кто запускает.** Владелец и люди, с которыми он делится (как с agentsoul). Поэтому ядро ищет `python3`, затем `python`, и проверяет версию ≥ 3.9. Без Python выдаётся понятное сообщение. CI гоняет Python 3.9 и 3.12.

## Приёмка

- Тесты ядра на эталонных примерах, посчитанных вручную или сверенных с известными значениями (NPV/IRR, график аннуитета, безубыточность, сходимость трёх форм).
- Сквозной пример `examples/edtech/`: входы → три формы, юнит-экономика, runway, DCF, три сценария; `checks.json` без ошибок; `model.xlsx` открывается, ключевые ячейки — формулы.
- Валидатор плагина: frontmatter агентов и skills, запрещённые поля, все ссылки `finance-soul:<имя>` существуют, бюджет хука.
- Живая проверка: `claude --plugin-dir plugins/finance-soul` в пустой папке → setup → модель.
- Публикация: публичный репозиторий `aibatjardem/finance-soul` на GitHub (просьба владельца «в моём гите»).

## Оставлено исполнителю

- Точные JSON-схемы входов и структура отчёта.
- Как проверять формулы xlsx без LibreOffice (например, dev-зависимость `formulas`/`pycel` только в тестах, или сверка структуры формул) — главное, чтобы значения в Excel совпадали с ядром.
- Как хук и агенты запускают ядро, если `openpyxl` не установлен (понятное сообщение с командой установки).
- Содержание методичек: на основе источников с разрешающей лицензией, переписано на русском, с атрибуцией в `NOTICE`.
